# DLO Segmentation — three-way wire / connector segmentation

Semantic segmentation of deformable linear objects (DLOs: cables, wire harnesses) from
RGB images. A synthetic dataset is rendered from labelled 4096-point harness point
clouds, and a SegFormer-B5 is trained to label every pixel
`{0 = background, 1 = wire, 2 = connector}`.

This README reproduces the **August 2026 result** end to end: the rendered dataset, the
trained checkpoint, and the reported metrics.

## The result being reproduced

Held-out synthetic validation split (1080 frames, three wire assemblies never seen in
training), plain argmax at native resolution:

| Metric | July baseline | August | Δ |
|---|---|---|---|
| IoU, connector | 0.7625 | **0.8025** | +4.0 pts |
| IoU, wire | 0.8603 | **0.8784** | +1.8 pts |
| Mean IoU | 0.8735 | **0.8929** | +1.9 pts |
| Connector precision / recall | 0.869 / 0.861 | **0.894 / 0.886** | both up |

The gain comes from two training-side changes only — the dataset is identical to the
July baseline's:

1. **Lovász-Softmax auxiliary loss** (`--lovasz-weight 0.5`) — a differentiable surrogate
   for the IoU the metric actually measures, instead of grading each pixel independently.
2. **Scale-only augmentation** (`--aug-zoom 0.5,0.5,1.0`) — with p=0.5, crop a random
   [0.5, 1.0] fraction and resize back, so connectors are seen at up to 2× size.

## Setup

```bash
python3 -m venv env && source env/bin/activate

```

Trained and evaluated on a single NVIDIA A40 (48 GB); training peaks at ~19.3 GB, so any
≥24 GB GPU is enough.

## Reproducing from scratch

### Inputs you need first

| Input | Path | Notes |
|---|---|---|
| Harness point clouds | `data/set2/<set>/` | 28 sets of 4096-point clouds + per-point class labels. The source dataset — not in git. |
| Textures / backdrops / clutter | `data/textures/`, `data/objects/` | CC0 assets (ambientCG, Poly Haven) used by the renderer. |
| Warm-start checkpoint | `results/realism_campaign/p39_cutoutneg/segformer_b5_warmstart/epoch_10.pth` | Binary wire model the three-way run initialises from — see the caveat in step 3. |

`data/` and `results/` are gitignored: both are regenerated by the steps below.

### 1. Render the RGB-D dataset (8,640 frames, ~40 min on 8 workers)

```bash
KIAT_OUTPUT_ROOT=data/render_3way_connscale3 \
KIAT_DATASET_MODE=phase13 \
KIAT_BG_DIR=data/textures/backgrounds_p4orig11 \
KIAT_DLO_UNICOLOR=1 \
KIAT_CONNECTOR_SCALE=3.0 \
python src/render_full_dataset.py --workers 8
```

Produces 1,440 source frames × 6 views = 8,640 RGB / depth / label images: 21 training
assemblies (1,260 sources) and 3 held out (180 sources). The split is at assembly level,
so no held-out wire is ever seen in training. Set IDs are non-contiguous — train is
`000, 002, 003, 004, 006, …, 031` and validation is `032, 034, 035` — so always count
sets rather than assuming a contiguous range.

The two environment variables that define this task:

- `KIAT_DLO_UNICOLOR=1` paints the whole harness one wire colour, so colour gives no
  shortcut for finding the connector — the model must use shape and context.
- `KIAT_CONNECTOR_SCALE=3.0` splats connector points with a disc ~3× the wire's
  on-screen width, which is the geometric cue that makes the class learnable
  (it took connector IoU from 0.47 to 0.76 in July).

Use `KIAT_BG_DIR=data/textures/backgrounds_p4orig11` (11 photos) as shown, **not** the
larger `data/textures/backgrounds/` pool — the enriched pool has been measured to wreck
real-world transfer.

### 2. Stage and re-encode to three classes

```bash
# render layout -> flat RGB/Depth/Label + train.txt/test.txt (6-class labels)
python src/prepare_dformer_data.py \
    --src-root data/render_3way_connscale3 \
    --dst-root data/dformer_dataset_3way_connscale3_raw \
    --clean

# 6-class {bg,wire,endpoint,bifurcation,connector,noise} -> 3-class {bg,wire,connector}
python src/reencode_labels_3way.py \
    --src data/dformer_dataset_3way_connscale3_raw \
    --dst data/dformer_dataset_3way_connscale3
```

Re-encoding maps `{0,5} → 0` (background), `{1,2,3} → 1` (whole cable body),
`{4} → 2` (connector). RGB and depth are symlinked, not copied.

Expected: `train.txt` 7,560 lines, `test.txt` 1,080 lines.

### 3. Warm-start checkpoint

The training run initialises from a binary (background / wire) SegFormer-B5 produced by
the earlier real-world campaign. **It cannot be rebuilt from this repository alone** — it
was trained on third-party real-cable data (MovingCables, CC-BY-SA) and photographic
object cutouts that are not redistributed here. Copy the checkpoint over as-is, or, to
stay entirely self-contained, drop `--init-checkpoint` from step 4 and train from the
ImageNet-pretrained `nvidia/mit-b5`. The relative gain from the two levers should hold,
but the absolute numbers in the table above will not match.

### 4. Train (30 epochs, ~5 h 52 m on one A40)

```bash
bash scripts/train_3way_lovasz_ab.sh <gpu> 0.5 lovasz050_zoom --aug-zoom 0.5,0.5,1.0
```

Writes to `results/realism_campaign/p3w_lovasz/lovasz050_zoom/`. The script pins every
other flag to the July baseline (`--num-classes 3 --class-weights 1,6,4 --dlo-weight 6.0
--batch-size 8 --lr 6e-5 --warmup-epochs 5 --seed 1234`), so the Lovász weight and the
zoom flag are the only variables. Drop the trailing `--aug-zoom` argument to train the
Lovász-only arm (0.7836 / 0.8791 / 0.8869).

### 5. Evaluate

```bash
python src/eval_3way_final.py \
    --ckpt results/realism_campaign/p3w_lovasz/lovasz050_zoom/best_model.pth \
    --data-dir data/dformer_dataset_3way_connscale3 \
    --out results/realism_campaign/p3w_lovasz/eval_final.json
```

Prints pooled IoU plus a per-held-out-set breakdown. Read the per-set table, not only the
pooled number: val set 035 alone carries 65.5 % of all connector pixels, so a pooled gain
can hide a single-assembly artefact. All three sets should improve (032 +0.035,
034 +0.046, 035 +0.038).

Add `--tta` for horizontal-flip test-time augmentation (0.8080 / 0.8812 / 0.8957),
reported separately from the headline.

### 6. Rebuild the deck figure

```bash
python src/build_august_deck_figure.py
```

Writes `results/presentations/KIAT_CREFLE_UPDATE_AUGUST2026/slide_compare.png` — the
before/after panel, using the val frames where the two models differ most on connector IoU.

## Notes for new work

- **Evaluate on a held-out set, and check every set.** Pooled metrics on this data are
  dominated by one assembly.
- **Report a stable level, not a peak.** Checkpoint metrics here are noisy enough that a
  single lucky epoch has been mistaken for a real gain before; the numbers above are the
  mean of the last five evaluations. `src/compare_3way_arms.py` does this comparison.
- **Change one thing at a time.** Every result in the table comes from a matched run where
  only the lever under test differs (same init, seed, data and schedule).
- **Dataset changes are the risky ones.** Several past render/dataset changes that improved
  synthetic scores made real-camera performance much worse. Synthetic IoU does not predict
  real-world transfer — validate on real footage before claiming a deployment win.
- These numbers are **synthetic-validation only**. Real-camera performance is measured
  separately and is not covered by them.
